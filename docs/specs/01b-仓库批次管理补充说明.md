## 一、业务背景

### 1.1 面料行业仓库核心业务规则

在纺织面料行业，仓库管理有其独特的层级结构：

```
仓库 (Warehouse)
    └── 库位 (Location)
        └── 缸号 (Batch/Dye Lot) ⭐
            └── 匹号 (Roll No) ⭐⭐⭐
```

### 1.2 层级关系说明

| 层级 | 名称 | 说明 | 示例 |
|------|------|------|------|
| 第一层 | 仓库 | 物理仓库 | 成品仓库A区 |
| 第二层 | 库位 | 仓库内具体位置 | A01-01-01 |
| 第三层 | 缸号 | 一次染色/生产的批次 | GD20260607001 |
| 第四层 | 匹号 | 每一匹布的唯一编号 | P001, P002 |

## 二、缸号与匹号规则 ⭐⭐⭐

### 2.1 核心业务规则

#### 规则一：同一产品 + 同一颜色 = 多个缸号

```
产品：纯棉针织面料 280g/m²
颜色：红色 C-001

├── 缸号：GD20260607001（第一批染色）
│   ├── 匹号：P001
│   ├── 匹号：P002
│   └── 匹号：P003
│
├── 缸号：GD20260608001（第二批染色）
│   ├── 匹号：P001    ← 注意：匹号可以重复！
│   ├── 匹号：P002
│   └── 匹号：P003
│
└── 缸号：GD20260609001（第三批染色）
    ├── 匹号：P001
    └── 匹号：P002
```

#### 规则二：同一缸号内匹号不能重复

```
缸号：GD20260607001

❌ 错误示例：
├── 匹号：P001  ← 匹号重复！
├── 匹号：P002
└── 匹号：P001  ← 匹号重复！

✅ 正确示例：
├── 匹号：P001
├── 匹号：P002
└── 匹号：P003
```

#### 规则三：不同缸号之间匹号可以重复

```
缸号：GD20260607001（第一批）
├── 匹号：P001
├── 匹号：P002
└── 匹号：P003

缸号：GD20260608001（第二批）
├── 匹号：P001  ← 不同缸号，匹号可以重复
├── 匹号：P002  ← 不同缸号，匹号可以重复
└── 匹号：P003  ← 不同缸号，匹号可以重复
```

### 2.2 唯一性约束

| 约束项 | 约束规则 | 约束方式 |
|--------|----------|----------|
| 缸号 | 同一产品+颜色下缸号唯一 | 缸号+产品ID+颜色ID 唯一 |
| 匹号 | 同一缸号内匹号唯一 | 匹号+缸号 唯一 |
| 匹号（全局）| 匹号可以重复 | 无全局唯一约束 |

### 2.3 编码规则

#### 缸号编码规则
```
GD + YYYYMMDD + 序号（3位）
示例：GD20260607001
```

| 部分 | 含义 | 格式 |
|------|------|------|
| GD | 缸号前缀 | 固定 |
| YYYYMMDD | 生产/入库日期 | 8位数字 |
| 序号 | 当日第几个缸 | 3位数字 |

#### 匹号编码规则
```
P + 序号（3位）
示例：P001, P002, P003...
```

| 部分 | 含义 | 格式 |
|------|------|------|
| P | 匹号前缀 | 固定 |
| 序号 | 当缸第几匹 | 3位数字（从001开始） |

## 三、数据结构设计

### 3.1 批次表设计（inventory_batches）

```sql
CREATE TABLE inventory_batches (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    
    -- 基本信息
    batch_no VARCHAR(50) NOT NULL,           -- 缸号：GD20260607001
    roll_no VARCHAR(50) NOT NULL,           -- 匹号：P001
    
    -- 产品和颜色（唯一定位一批布）
    product_id UUID NOT NULL REFERENCES products(id),
    color_variant_id UUID REFERENCES product_color_variants(id),  -- 颜色变体ID
    
    -- 仓库和库位
    warehouse_id UUID NOT NULL REFERENCES warehouses(id),
    location_code VARCHAR(50),               -- 库位：如 A01-01-01
    
    -- 数量
    quantity DECIMAL(12, 4) NOT NULL DEFAULT 0,      -- 数量（如：150米）
    unit VARCHAR(20) DEFAULT 'meter',                -- 单位：米
    
    -- 生产信息
    production_date DATE,                     -- 生产日期
    manufacture_no VARCHAR(50),              -- 生产批号
    
    -- 来源信息
    source_type VARCHAR(20),                 -- 来源：PURCHASE/PRODUCTION/TRANSFER
    source_id UUID,                          -- 来源单据ID
    source_no VARCHAR(50),                   -- 来源单据号
    
    -- 质检信息
    quality_status VARCHAR(20) DEFAULT 'PASSED',  -- 质检状态
    color_formula_id UUID,                   -- 关联的颜色配方
    
    -- 状态
    status VARCHAR(20) DEFAULT 'ACTIVE',     -- ACTIVE/FROZEN/CLOSED
    
    -- 审计字段
    created_at TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP,
    created_by UUID,
    updated_by UUID,
    
    -- 唯一约束
    CONSTRAINT uk_batch_roll UNIQUE (product_id, color_variant_id, batch_no, roll_no)
);

-- 索引
CREATE INDEX idx_batches_batch_no ON inventory_batches(batch_no);
CREATE INDEX idx_batches_product_color ON inventory_batches(product_id, color_variant_id);
CREATE INDEX idx_batches_warehouse ON inventory_batches(warehouse_id);
CREATE INDEX idx_batches_source ON inventory_batches(source_type, source_id);
CREATE INDEX idx_batches_status ON inventory_batches(status);
```

### 3.2 匹号生成逻辑

```typescript
// 匹号生成服务
async generateRollNo(batchId: UUID): Promise<string> {
    // 1. 获取当前缸号内已有的最大匹号
    const maxRoll = await this.inventoryBatchRepository
        .createQueryBuilder('batch')
        .where('batch.batch_no = :batchNo', { batchNo: currentBatchNo })
        .orderBy('batch.roll_no', 'DESC')
        .getOne();
    
    // 2. 如果没有，取001；否则+1
    let nextNumber = 1;
    if (maxRoll) {
        const currentNo = parseInt(maxRoll.roll_no.replace('P', ''));
        nextNumber = currentNo + 1;
    }
    
    // 3. 生成匹号
    return `P${nextNumber.toString().padStart(3, '0')}`;
}
```

### 3.3 缸号生成逻辑

```typescript
// 缸号生成服务
async generateBatchNo(productId: UUID, colorVariantId: UUID): Promise<string> {
    // 1. 获取日期
    const today = new Date();
    const dateStr = format(today, 'yyyyMMdd');
    
    // 2. 获取当日该产品+颜色的最大序号
    const maxBatch = await this.inventoryBatchRepository
        .createQueryBuilder('batch')
        .where('batch.product_id = :productId', { productId })
        .andWhere('batch.color_variant_id = :colorVariantId', { colorVariantId })
        .andWhere('batch.batch_no LIKE :prefix', { prefix: `GD${dateStr}%` })
        .orderBy('batch.batch_no', 'DESC')
        .getOne();
    
    // 3. 如果没有，取001；否则+1
    let nextNumber = 1;
    if (maxBatch) {
        const lastNo = maxBatch.batch_no.slice(-3);
        nextNumber = parseInt(lastNo) + 1;
    }
    
    // 4. 生成缸号
    return `GD${dateStr}${nextNumber.toString().padStart(3, '0')}`;
}
```

## 四、业务流程

### 4.1 采购入库流程（匹号生成）

```
采购入库单确认
        ↓
系统生成缸号（GD20260607001）
        ↓
入库第一匹布 → 手动输入匹号（P001）或系统自动生成
        ↓
入库第二匹布 → 系统自动生成匹号（P002）
        ↓
入库第三匹布 → 系统自动生成匹号（P003）
        ↓
...
        ↓
同一缸号匹号：P001, P002, P003, P004...
```

### 4.2 生产入库流程

```
生产工单完工
        ↓
系统生成缸号
        ↓
选择或创建新的缸号
        ↓
每匹布入库时自动生成匹号
        ↓
记录匹长、重量等信息
```

### 4.3 销售发货流程

```
客户下单（指定颜色）
        ↓
选择缸号（可指定或FIFO自动选择）
        ↓
选择匹号（同一缸号内不能重复）
        ↓
系统检查匹号唯一性
        ↓
发货确认
```

## 五、匹号唯一性校验

### 5.1 入库时校验

```typescript
// 入库服务
async addToBatch(
    productId: UUID,
    colorVariantId: UUID,
    batchNo: string,
    rollNo: string
): Promise<void> {
    // 1. 检查同一缸号内匹号是否已存在
    const existing = await this.inventoryBatchRepository.findOne({
        where: {
            productId,
            colorVariantId,
            batchNo,
            rollNo
        }
    });
    
    if (existing) {
        throw new Error(`匹号 ${rollNo} 在缸号 ${batchNo} 中已存在，请使用其他匹号`);
    }
    
    // 2. 创建批次记录
    const batch = this.inventoryBatchRepository.create({
        productId,
        colorVariantId,
        batchNo,
        rollNo,
        quantity: 0,
        warehouseId: defaultWarehouseId
    });
    
    await this.inventoryBatchRepository.save(batch);
}
```

### 5.2 发货时匹号校验

```typescript
// 发货服务 - 选择批次时
async selectBatchForDelivery(
    productId: UUID,
    colorVariantId: UUID,
    quantity: number
): Promise<BatchSelection[]> {
    // 1. FIFO选择缸号
    // 2. 在选定缸号内选择匹号（避免重复）
    
    const batches = await this.inventoryBatchRepository
        .createQueryBuilder('batch')
        .leftJoin('batch.deliveryItems', 'di')  // 已发货的匹号
        .where('batch.product_id = :productId', { productId })
        .andWhere('batch.color_variant_id = :colorVariantId', { colorVariantId })
        .andWhere('batch.quantity > 0')
        .andWhere('batch.status = :status', { status: 'ACTIVE' })
        .orderBy('batch.production_date', 'ASC')  // FIFO
        .getMany();
    
    // 3. 过滤已完全发货的匹号
    const availableBatches = batches.filter(b => {
        const shippedQty = b.deliveryItems?.reduce((sum, di) => sum + di.quantity, 0) || 0;
        return b.quantity - shippedQty > 0;
    });
    
    return availableBatches;
}
```

## 六、库存查询

### 6.1 按产品+颜色+缸号查询

```sql
-- 查询某产品某颜色的所有缸号
SELECT 
    pb.product_name,
    pcv.color_name,
    pb.batch_no,
    COUNT(pb.id) as roll_count,
    SUM(pb.quantity) as total_quantity
FROM inventory_batches pb
JOIN products p ON pb.product_id = p.id
JOIN product_color_variants pcv ON pb.color_variant_id = pcv.id
WHERE p.id = 'product-uuid'
  AND pcv.id = 'color-variant-uuid'
GROUP BY pb.product_id, pb.color_variant_id, pb.batch_no
ORDER BY pb.batch_no DESC;
```

### 6.2 按缸号查询匹号列表

```sql
-- 查询某缸号的所有匹号
SELECT 
    batch_no,
    roll_no,
    quantity,
    unit,
    location_code,
    production_date,
    quality_status
FROM inventory_batches
WHERE product_id = 'product-uuid'
  AND color_variant_id = 'color-variant-uuid'
  AND batch_no = 'GD20260607001'
ORDER BY roll_no;
```

### 6.3 匹号重复性检查

```sql
-- 检查匹号在全局是否重复（不同缸号）
SELECT 
    roll_no,
    COUNT(DISTINCT batch_no) as batch_count,
    array_agg(batch_no) as batches
FROM inventory_batches
WHERE product_id = 'product-uuid'
  AND color_variant_id = 'color-variant-uuid'
GROUP BY roll_no
HAVING COUNT(DISTINCT batch_no) > 1;

-- 结果示例：
-- roll_no | batch_count | batches
-- P001    | 3          | {GD20260607001, GD20260608001, GD20260609001}
-- 说明匹号P001在3个不同的缸号中存在（这是允许的）
```

## 十、注意事项

### 10.1 开发要点

1. **匹号唯一性约束**：`batch_no + roll_no` 在同一产品+颜色下唯一
2. **自动生成逻辑**：匹号在同一缸号内自动递增
3. **匹号可重复**：不同缸号之间匹号可以相同
4. **批次冻结**：冻结缸号时，该缸号内匹号一并冻结

### 10.2 业务要点

1. **入库必须指定缸号**：同一缸号的匹才能一起入库
2. **发货可选缸号**：可以只发某缸号内的部分匹
3. **匹号追溯**：每个匹号都可以追溯完整的来源和去向

## 十一、与其他模块的关联

### 11.1 与采购模块

- 采购入库 → 生成缸号 → 登记匹号
- 匹号与采购单号关联

### 11.2 与生产模块

- 生产入库 → 生成缸号 → 登记匹号
- 匹号与生产工单关联

### 11.3 与销售模块

- 销售发货 → 选择缸号和匹号
- 匹号与发货单关联

### 11.4 与质检模块

- 每个匹号都可单独质检
- 质检结果记录到匹号级别
