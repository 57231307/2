## 一、业务背景

### 1.1 面料行业核心业务规则

在纺织面料行业，**同一个产品可以有多个颜色变体，每个颜色变体都有独立的编号和价格**，这是面料行业的核心业务特点：

**示例**：
```
产品：纯棉针织面料 280g/m²
├── 颜色变体：红色 #C001 - 单价：¥45.00/米
├── 颜色变体：蓝色 #C002 - 单价：¥42.00/米
├── 颜色变体：绿色 #C003 - 单价：¥43.00/米
└── 颜色变体：黄色 #C004 - 单价：¥44.00/米
```

### 1.2 为什么要支持产品颜色变体？

| 传统模式 | 颜色变体模式 |
|----------|-------------|
| 每个颜色作为一个独立产品 | 颜色作为产品的变体属性 |
| 产品编码重复 | 共享基础产品编码 |
| 价格维护繁琐 | 统一管理基础价格，颜色变体可覆盖 |
| 库存管理分散 | 库存按颜色变体分别管理 |

## 二、数据结构设计

### 2.1 产品颜色变体表（product_color_variants）

```sql
CREATE TABLE product_color_variants (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    product_id UUID NOT NULL REFERENCES products(id),
    color_no VARCHAR(50) NOT NULL UNIQUE,
    color_name VARCHAR(200) NOT NULL,
    color_code VARCHAR(50),
    
    -- 价格管理
    standard_cost DECIMAL(12, 4),           -- 标准成本（可覆盖产品基础成本）
    sale_price DECIMAL(12, 4) NOT NULL,    -- 销售价格（必须设置）
    wholesale_price DECIMAL(12, 4),         -- 批发价格
    vip_price DECIMAL(12, 4),              -- VIP价格
    
    -- 颜色信息
    color_formula_id UUID REFERENCES color_formulas(id),  -- 关联颜色配方
    lab_l DECIMAL(8, 2),                   -- LAB值L
    lab_a DECIMAL(8, 2),                   -- LAB值a
    lab_b DECIMAL(8, 2),                   -- LAB值b
    rgb_color VARCHAR(20),                  -- RGB颜色值（如 #FF0000）
    hex_color VARCHAR(20),                   -- HEX颜色值
    
    -- 图片管理
    images JSONB DEFAULT '[]',             -- 颜色变体图片列表
    
    -- 规格参数
    weight DECIMAL(10, 2),                  -- 克重（g/m²）
    width DECIMAL(10, 2),                   -- 幅宽（cm）
    
    -- 状态管理
    status VARCHAR(20) DEFAULT 'ACTIVE',
    is_default BOOLEAN DEFAULT FALSE,      -- 是否为默认颜色
    
    -- 审计字段
    created_at TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP,
    created_by UUID,
    updated_by UUID,
    
    CONSTRAINT uk_product_color UNIQUE (product_id, color_no)
);

CREATE INDEX idx_product_color_variants_product ON product_color_variants(product_id);
CREATE INDEX idx_product_color_variants_color_no ON product_color_variants(color_no);
CREATE INDEX idx_product_color_variants_status ON product_color_variants(status);
```

### 2.2 产品表更新（products）

```sql
-- products表增加字段
ALTER TABLE products ADD COLUMN has_color_variants BOOLEAN DEFAULT FALSE;
ALTER TABLE products ADD COLUMN default_variant_id UUID REFERENCES product_color_variants(id);
```

## 三、业务流程

### 3.1 产品颜色变体创建流程

```
1. 创建基础产品（基础信息、规格）
        ↓
2. 添加颜色变体（颜色编号、颜色名称）
        ↓
3. 设置颜色变体价格（必填）
        ↓
4. 关联颜色配方（可选）
        ↓
5. 上传颜色变体图片（可选）
        ↓
6. 保存颜色变体
```

### 3.2 订单中的颜色变体选择

```
客户下单
    ↓
选择产品（显示基础信息）
    ↓
选择颜色变体（显示可选颜色列表和价格）
    ↓
系统自动带出：
  - 颜色编号
  - 销售价格（来自颜色变体）
  - 颜色配方（用于质检）
    ↓
确认订单
```

## 五、API接口设计

### 5.1 产品颜色变体接口

#### 5.1.1 创建颜色变体
```
POST /api/v1/product-color-variants
```

**请求参数**：
```json
{
  "productId": "product-uuid",
  "colorNo": "C-001",
  "colorName": "红色",
  "salePrice": 45.00,
  "standardCost": 30.00,
  "colorFormulaId": "formula-uuid",
  "labL": 45.5,
  "labA": 58.2,
  "labB": 25.8,
  "weight": 280,
  "width": 150,
  "images": []
}
```

```
GET /api/v1/product-color-variants?productId={productId}
```

**响应**：

## 六、价格计算逻辑

### 6.1 订单价格获取规则

```
订单选择产品颜色时：
1. 如果选择了颜色变体：
   - 使用颜色变体的 sale_price
   - 使用颜色变体的 standard_cost
2. 如果未选择颜色变体：
   - 使用产品的默认颜色变体价格
   - 如果没有默认变体，使用产品的 base_price
```

### 6.2 价格优先级

| 优先级 | 来源 | 说明 |
|--------|------|------|
| 1 | 颜色变体价格 | 颜色变体单独设置的价格 |
| 2 | 产品默认价格 | 产品级别设置的默认价格 |
| 3 | 系统默认价格 | 系统中配置的默认价格 |

## 七、库存管理

### 7.1 库存按颜色变体管理

- 批次表中关联 `color_variant_id`
- 同一产品的不同颜色变体，库存分开管理
- 库存查询时可按颜色筛选

### 7.2 批次表更新

```sql
-- inventory_batches表增加字段
ALTER TABLE inventory_batches ADD COLUMN color_variant_id UUID REFERENCES product_color_variants(id);
```

## 十一、开发注意事项

### 11.1 关键点

1. **颜色编号唯一性**：同一产品下颜色编号不能重复
2. **价格必填**：每个颜色变体必须有销售价格
3. **库存隔离**：库存按颜色变体分别管理
4. **配方关联**：颜色变体可关联颜色配方（用于质检）
5. **默认值设置**：可为产品设置默认颜色变体

### 11.2 性能优化

- 颜色变体查询时使用缓存
- 批量导入时使用事务
- 图片使用CDN加速
