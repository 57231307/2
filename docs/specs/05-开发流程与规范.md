## 1. Git 分支策略

### 1.1 分支命名规范

| 分支类型 | 命名规范 | 说明 |
|----------|---------|------|
| 主分支 | `main` | 生产环境代码 |
| 开发分支 | `develop` | 开发环境代码 |
| 功能分支 | `feature/feature-name` | 新功能开发 |
| 修复分支 | `fix/bug-name` | Bug 修复 |
| 发布分支 | `release/v1.0.0` | 版本发布 |
| 热修复分支 | `hotfix/hotfix-name` | 生产环境紧急修复 |

### 1.2 Git 工作流

```mermaid
gitGraph
    commit id: "init"
    branch develop
    checkout develop
    commit id: "dev-1"
    branch feature/sales
    checkout feature/sales
    commit id: "feat-1"
    commit id: "feat-2"
    checkout develop
    merge feature/sales
    commit id: "dev-2"
    branch release/v1.0.0
    checkout release/v1.0.0
    commit id: "rc-1"
    checkout main
    merge release/v1.0.0 tag: "v1.0.0"
    checkout develop
    merge release/v1.0.0
    branch hotfix/urgent-fix
    checkout hotfix/urgent-fix
    commit id: "fix-1"
    checkout main
    merge hotfix/urgent-fix tag: "v1.0.1"
    checkout develop
    merge hotfix/urgent-fix
```

### 1.3 提交信息规范

```bash
# 格式
<type>(<scope>): <subject>

# 类型
feat: 新功能
fix: 修复 bug
docs: 文档修改
style: 代码格式调整
refactor: 重构
test: 测试相关
chore: 构建/工具链

# 示例
feat(sales): 添加销售订单导出功能
fix(inventory): 修复库存扣减并发问题
docs(readme): 更新部署文档
```

## 3. 开发工作流

### 3.1 标准开发流程

```mermaid
flowchart TD
    A[需求分析] --> B[技术方案设计]
    B --> C[创建功能分支]
    C --> D[代码开发]
    D --> E[本地测试]
    E --> F[提交代码]
    F --> G[创建 MR/PR]
    G --> H[代码审查]
    H --> I{通过?}
    I -->|是| J[合并到 develop]
    I -->|否| K[修改代码]
    K --> F
```

## 4. 代码审查

### 4.1 审查清单

- [ ] 代码符合项目规范
- [ ] 已添加必要的单元测试
- [ ] 没有引入安全漏洞
- [ ] 没有性能问题
- [ ] API 文档已更新
- [ ] 数据库迁移已验证
